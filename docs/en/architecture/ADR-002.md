# ADR-002 · Processing Pipeline

- **Status:** Accepted
- **Date:** 2026-09-01

## Context

The Engine processes document collections by executing a sequence of independent processing stages.

The current implementation already follows a well-defined execution order where each stage is responsible for a single task and only executes when its prerequisites are satisfied.

This document formalizes the processing pipeline currently implemented by the Engine.

---

## Decision

The Engine shall process every document through a sequential pipeline composed of independent stages.

Each stage has a single responsibility and is executed only when required.

The completion of a stage enables the execution of the next one.

---

## Current Pipeline

The current implementation executes the following stages.

```text
Discover Documents
        │
        ▼
Load Processing State
        │
        ▼
Filter Pending Documents
        │
        ▼
Retrieve Number of Pages
        │
        ▼
Persist Processing State
        │
        ▼
Write Google Sheets Row
        │
        ▼
Persist Processing State
```

Each document advances independently through the pipeline.

The completion or failure of one document does not affect the processing of the remaining documents.

---

## Processing Stages

### Stage 1 — Discover Documents

Responsible for obtaining the collection of documents to be processed.

Current implementation:

- DriveService

Output:

- Collection of `PdfFile` objects.

---

### Stage 2 — Load Processing State

Responsible for recovering the latest processing state associated with each document.

Current implementation:

- ProcessedFilesRepository

Output:

- Hydrated `PdfFile` objects.

---

### Stage 3 — Filter Pending Documents

Responsible for determining whether each document still requires processing.

Current implementation:

- ElectronicIndexService.getPendingFiles()

Documents are considered pending when at least one processing stage has not been completed.

---

### Stage 4 — Retrieve Number of Pages

Responsible for obtaining the total number of pages of a document.

Current implementation:

- CloudRunClient

This stage is executed only when:

```text
pages == null
```

---

### Stage 5 — Persist Processing State

Responsible for storing the current processing state after completing the previous stage.

Current implementation:

- ProcessedFilesRepository

This persistence occurs immediately after every completed stage.

---

### Stage 6 — Write Processing Result

Responsible for writing the processed information into Google Sheets.

Current implementation:

- GoogleSheetsService

This stage is executed only when:

```text
sheetRow == null
```

---

### Stage 7 — Persist Processing State

Responsible for storing the updated processing state after writing the processing result.

Current implementation:

- ProcessedFilesRepository

---

## Pipeline Characteristics

The current pipeline follows these principles.

### Sequential

Stages execute in a predefined order.

---

### Independent

Each stage has a single responsibility.

---

### Conditional

A stage executes only when required.

Already completed stages are skipped.

---

### Incremental

Each completed stage advances the processing state.

---

### Idempotent

Executing the pipeline multiple times over the same documents shall not generate duplicated work.

---

### Resumable

The pipeline may resume from the last successfully completed stage.

Restarting the complete processing is never required.

---

## Consequences

This pipeline provides:

- Predictable execution.
- Fault tolerance.
- Safe recovery.
- Incremental processing.
- Elimination of duplicated work.

Future versions of the Engine may introduce additional stages without modifying the existing processing model.

---

## Notes

This ADR documents the processing pipeline currently implemented by the Engine.

It does not define how stages are configured or extended.

Pipeline extensibility will be addressed by future Architectural Decision Records.
