# ADR-002 · Pipeline de Procesamiento

- **Estado:** Aprobado
- **Fecha:** 2026-09-01

## Contexto

El Motor procesa conjuntos de documentos mediante la ejecución de una secuencia de etapas independientes.

La implementación actual ya sigue un orden de ejecución bien definido, donde cada etapa es responsable de una única tarea y solo se ejecuta cuando se cumplen sus prerrequisitos.

Este documento formaliza el pipeline de procesamiento actualmente implementado por el Motor.

---

## Decisión

El Motor procesará cada documento mediante un pipeline secuencial compuesto por etapas independientes.

Cada etapa tiene una única responsabilidad y solo se ejecuta cuando es necesaria.

La finalización de una etapa habilita la ejecución de la siguiente.

---

## Pipeline Actual

La implementación actual ejecuta las siguientes etapas.

```text
Descubrir Documentos
        │
        ▼
Cargar Estado de Procesamiento
        │
        ▼
Filtrar Documentos Pendientes
        │
        ▼
Obtener Número de Páginas
        │
        ▼
Persistir Estado de Procesamiento
        │
        ▼
Escribir Fila en Google Sheets
        │
        ▼
Persistir Estado de Procesamiento
```

Cada documento avanza de manera independiente a través del pipeline.

La finalización o el fallo de un documento no afecta el procesamiento de los demás.

---

## Etapas del Pipeline

### Etapa 1 — Descubrir Documentos

Responsable de obtener la colección de documentos que serán procesados.

Implementación actual:

- DriveService

Salida:

- Colección de objetos `PdfFile`.

---

### Etapa 2 — Cargar Estado de Procesamiento

Responsable de recuperar el último estado de procesamiento asociado a cada documento.

Implementación actual:

- ProcessedFilesRepository

Salida:

- Objetos `PdfFile` hidratados.

---

### Etapa 3 — Filtrar Documentos Pendientes

Responsable de determinar si un documento aún requiere procesamiento.

Implementación actual:

- ElectronicIndexService.getPendingFiles()

Un documento se considera pendiente cuando al menos una etapa del procesamiento aún no ha sido completada.

---

### Etapa 4 — Obtener Número de Páginas

Responsable de obtener el número total de páginas de un documento.

Implementación actual:

- CloudRunClient

Esta etapa solo se ejecuta cuando:

```text
pages == null
```

---

### Etapa 5 — Persistir Estado de Procesamiento

Responsable de almacenar el estado actual del procesamiento después de completar la etapa anterior.

Implementación actual:

- ProcessedFilesRepository

Esta persistencia ocurre inmediatamente después de cada etapa completada.

---

### Etapa 6 — Escribir Resultado del Procesamiento

Responsable de escribir la información procesada en Google Sheets.

Implementación actual:

- GoogleSheetsService

Esta etapa solo se ejecuta cuando:

```text
sheetRow == null
```

---

### Etapa 7 — Persistir Estado de Procesamiento

Responsable de almacenar el estado actualizado después de escribir el resultado.

Implementación actual:

- ProcessedFilesRepository

---

## Características del Pipeline

El pipeline actual sigue los siguientes principios.

### Secuencial

Las etapas se ejecutan en un orden predefinido.

---

### Independiente

Cada etapa tiene una única responsabilidad.

---

### Condicional

Una etapa solo se ejecuta cuando es necesaria.

Las etapas ya completadas son omitidas.

---

### Incremental

Cada etapa completada hace avanzar el estado del procesamiento.

---

### Idempotente

Ejecutar el pipeline varias veces sobre los mismos documentos no genera trabajo duplicado.

---

### Reanudable

El pipeline puede continuar desde la última etapa completada exitosamente.

Nunca es necesario reiniciar el procesamiento completo.

---

## Consecuencias

Este pipeline proporciona:

- Ejecución predecible.
- Tolerancia a fallos.
- Recuperación segura.
- Procesamiento incremental.
- Eliminación de trabajo duplicado.

Versiones futuras del Motor podrán incorporar nuevas etapas sin modificar el modelo de procesamiento existente.

---

## Notas

Este ADR documenta el pipeline de procesamiento actualmente implementado por el Motor.

No define cómo se configuran ni cómo se extienden las etapas.

La extensibilidad del pipeline será abordada en futuros Registros de Decisión Arquitectónica.
