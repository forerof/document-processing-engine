# ADR-000 · Propósito del proyecto

- **Estado:** Aceptado
- **Fecha:** 2026-09-01

## Contexto

El proyecto surgió de la necesidad de automatizar tareas repetitivas comunes en los procesos de gestión documental.

El motor de procesamiento actual ya implementa una canalización capaz de:

- Descubrir documentos desde una fuente.

- Leer y enriquecer los metadatos de los documentos.

- Mantener el estado del procesamiento.

- Guardar los resultados del procesamiento.

- Reanudar de forma segura las ejecuciones interrumpidas.

La experiencia adquirida durante el desarrollo de este motor demostró que este modelo de procesamiento no se limita a un único caso de uso, sino que puede reutilizarse en diferentes escenarios de automatización documental.

Por este motivo, el proyecto evoluciona de una implementación específica a una biblioteca de código abierto reutilizable, configurable y extensible llamada **document-processing-engine**.

---

## Planteamiento del problema

`document-processing-engine` proporciona una forma estructurada y configurable de automatizar el procesamiento de colecciones de documentos mediante etapas de procesamiento independientes.

Su objetivo es reducir la complejidad de la creación de soluciones de procesamiento de documentos al proporcionar una arquitectura de procesamiento reutilizable.

--

## Decisión

`document-processing-engine` será una biblioteca de código abierto cuyo propósito es proporcionar un motor de procesamiento de documentos configurable capaz de crear flujos de procesamiento de documentos reutilizables y extensibles.

El motor **no** pretende reemplazar un Sistema de Gestión Documental (DMS). En cambio, está diseñado para convertirse en un componente reutilizable que se puede integrar en las soluciones de gestión documental existentes para automatizar tareas específicas de procesamiento de documentos.

--

## Alcance

El motor admite la automatización de operaciones como:

- Descubrimiento de documentos.

- Extracción de metadatos.

- Transformación de información.

- Enriquecimiento de datos mediante componentes externos.

- Validación.

- Clasificación.

- Persistencia del estado de procesamiento.

- Persistencia de resultados.

Las etapas de procesamiento concretas dependen de la configuración de cada implementación.

--

## Fuera del alcance

`document-processing-engine` **no** pretende ser:

- Un sistema de gestión documental (DMS).

- Un repositorio de documentos.

- Un visor de documentos.

- Un sistema de gestión de registros.

- Una interfaz de usuario.

- Una plataforma de gestión de flujos de trabajo.

Estas funcionalidades pertenecen a proyectos desarrollados sobre el motor.

--

## Modelo de procesamiento

La unidad lógica de procesamiento es una **colección de documentos**.

Cada documento se procesa de forma independiente, compartiendo la misma canalización de procesamiento y contexto de ejecución.

--

## Principios arquitectónicos

El motor siempre deberá respetar los siguientes principios:

### 1. Inmutabilidad del documento

El documento original nunca debe modificarse.

Toda la información generada debe almacenarse independientemente del documento fuente.

---

### 2. Procesamiento idempotente

La ejecución repetida del mismo proceso sobre la misma colección de documentos no debe generar resultados duplicados o inconsistentes.

--

### 3. Persistencia del estado

Cada etapa de procesamiento debe conservar su estado de ejecución para permitir:

- Reanudación de la ejecución.

- Auditabilidad.

- Recuperación de errores.

- Trazabilidad.

--

### 4. Extensibilidad

Se deben añadir nuevas funcionalidades sin modificar el núcleo del motor.

--

### 5. Configurabilidad

El comportamiento del motor debe estar determinado por la configuración, en lugar de por valores predefinidos o implementaciones específicas de la tecnología.

--

## Consecuencias

Como consecuencia de esta decisión:

- El proyecto evoluciona hacia un motor de procesamiento reutilizable.

- Las integraciones específicas de la tecnología se irán desacoplando progresivamente del núcleo del motor.

- Se incorporará funcionalidad adicional mediante componentes independientes. - Diferentes proyectos podrán reutilizar la misma arquitectura de procesamiento sin modificar el motor.

--

## Notas

Este Registro de Decisiones Arquitectónicas **no** introduce cambios funcionales en el motor de procesamiento existente.

Su propósito es documentar la visión del proyecto y establecer los principios arquitectónicos que guiarán su evolución hacia una biblioteca de procesamiento de documentos configurable y reutilizable.
